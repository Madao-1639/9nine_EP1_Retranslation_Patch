# 脚本文本模型

一个 `.scn` 的根对象是 `{hash, name, outlines, scenes}`。文本都在 `scenes[]` 里。

## 1. 对白行 `scenes[].texts[i]`

17 个脚本共 **9327 行**，arity 恒为 6（1 行为 7）。依据：`resource/official_scn/scn` 的 17 个脚本经 `tool/mdf.py`（`MdfScript.iter_messages()`）逐行解析，行数合计与 `resource/official_jp/_index.json` 的 `messages` 合计 9327 一致。

```
[0] speaker_jp     角色原名（日文），语言无关，保留不译
[1] speaker_alt    次名槽（多为 null），不译
[2] blocks         语言块列表，官方的**恒为 3 个**：jp / en / cn；补丁产物为 4 个（见 §7）
[3] attrs          属性（[{name,pan,type,voice}] | null），语音文件在这里，不是行内标记
[4] flag           整数（80 / 110 …）
[5] commands       引擎指令容器（bg/bgm/face/…），无文本
```

## 2. 语言块 `blocks[k]`

```
[0] name      该语言下的角色显示名（コスプレイヤー / Cosplayer / 角色扮演者），可为 null
[1] text      正文：含 ruby `[よみ,3]`、换行 `\\n`、控制码 `%p-1;` / `%f...;` / `#;`
[2] plain     正文的**读音版**：ruby 展开成读音、删行内标记、删换行
[3] plain2    正文的**基字版**：ruby 展开成基字、删行内标记、删换行
```

官方脚本的 `blocks` 长度恒为 3；按 cn 块的 arity 分：6932 行为 2（只有名+正文）、2395 行为 4。依据：`resource/official_scn/scn`（`scenes[].texts[i][2]` 是 `blocks`，取 `blocks[2]` 的子项数）。

**arity 的触发条件是「正文含行内标记」**（换行或 `%…;` / `#…;`）：jp 轨 2444 个 arity-4 = 2395 行含换行 + 49 行只含控制码；纯文本行不需要 plain。

**ruby 语法细则**（全作只有 3 处，都在 jp 轨）：`[よみ,N]` 后面紧跟的 **N+1** 个字是基字，N 不是基字总数。

```
a01 scene0 row1  text   = 俺の住む街、『[しろみつがわ,3]白巳津川』が…
                 plain  = 俺の住む街、『しろみつがわ』が…    ← 读音版
                 plain2 = 俺の住む街、『白巳津川』が…        ← 基字版（3+1 = 4 字区间）
```

无 ruby 时两个变体同值，官方**存同一个字符串槽**：4839 个 arity-4 块里 4836 同槽，只有那 3 行 ruby 分槽。依据：`tool/mdf.plain_variants()` 的规则对这 4839 块反推，**命中 4839/4839**（含 100 个带控制码的块）；单元用例与 oracle 见 `script/verify_plain.py`。

语料侧的 `plain` 必须逐槽等于 `mdf.plain_variants(text)`。产物里 plain 是**现算**的、不读语料该字段，但语料若与规则不一致，任何「照语料写 plain」的新路径都会错。当前已全量对齐（2395 行有 plain，0 违反）。

> ⚠️ 旧版本（已修）曾把两槽写反（称 `plain` = 去 ruby、`plain2` = 只留基字），且 `plain_of()` 只删 `[よみ,N]` 不删后随的基字、也不删控制码，会产出 `しろみつがわ白巳津川` 这种两不像的结果。转轨时若看到 plain 里残留 `%p-1;` 之类，就是这个 bug。

**本作没有 `length` 字段**（与《纯白交响曲 FHD》的页 length 不同），换文本只改字符串池，不需要重算长度，也就不需要完整对象图序列化器。

## 3. 槽位共享（回写必须处理）

| 现象 | 计数 | 影响 |
|---|---|---|
| 跨语言主文本槽互不相同 | 8845 / 9327 | 常规情形：追加新串 + 改指向即可 |
| **jp 与 cn 的正文槽同槽** | 482 / 9327 | 该行 jp/cn 本就是同一份文本（官方未译的短句）；其中 460 行的民汉文本与官中相同，无需改动 |
| 同一块内三槽同源（cn） | 6932（arity 2 的块天然只有一个串） | 一次替换即可 |
| 块内 `[2]`/`[3]` 同槽 | 4836 / 4839 | 同时指向新 plain；两个 plain 变体同值时（无 ruby）产物必须共用一槽，`extend_lang.py` 已按值去重 |
| 显示名槽跨行共享 | 常见 | 只在值真的不同时才改；765 行需改（5 种显示名，民汉源是繁中字形，见 §6） |

同槽 = PSB 里**同一个偏移数组元素**（解析后两个路径指向同一字节位置）。这类位置无法只改一处指向，必须重建父列表（需要偏移加宽/重算，等价于完整序列化器）。这条限制只约束「覆盖 cn 轨」的三轨回写路径：该路径对这类行**保留官方原文**，影响 3 行（`a01` scene0 row62、`a05` scene0 row62、`a13` scene0 row156）；四轨路径（§7）不动官方三块、只追加新块，不受此限。这条限制只出现在已废弃的三轨路径里：同一字节位置被非 cn 路径引用就跳过（对应脚本 `writeback.py` / `verify_patch.py` / `verify_roundtrip.py` 已随路径废弃删除，需要复核时看 git 历史）。当前交付只走四轨，不受此限。

## 6. 语料字形归一与显示名基准（民汉残留）

民汉正文大体是简中，但残留少量繁体字形，一律**直接改在语料里**（`resource/chs_text/scripts/*.jsonl`），不做旁路覆盖：正文 8 行 + 词级 `执著`->`执着` 1 行 + 显示名 5 种（`与一` / `索菲缇娅` / `春风` / `希亚` / `发狂的男学生`，共 793 行）。

**显示名取值基准：以民汉正文用字为准，官方 cn 只用于「身份判定」。**

* 判定（该行该不该露真名）跟官方 `cn` 轨：`？？？` / `角色扮演者` / 真名的切换点与官方逐行一致（例：`a04` scene4 row249 `？？？` -> row270 真名）。
* 用字跟民汉正文：正文写 `索菲`（90 处）/ `索菲缇娅`（3 处）、`希亚`、`春风`、`与一`，显示名就必须同形。官方 `cn` 用 `蘇菲堤雅`，简化后是 `苏菲堤雅`，与正文两处都不同（苏/索、堤/缇）——早先按官方简化导致 `a04` scene4 row270 同一屏出现「显示名 苏菲堤雅 + 正文 我的名字叫索菲缇娅」，2024 修订已改为 `索菲缇娅`（299 行）。

**官方 `cn` 轨用注音符号表示「只知发音、不知汉字怎么写」（不是乱码，也不是缺字形）：**

| 位置 | `jp` | `cn`（官方） | 本项目 `sc` |
|---|---|---|---|
| 正文 21 行 | `コウサカ　ハルカ` / `ユウキ　ノア` | `ㄒㄧㄤㄅㄢˇㄔㄨㄣㄈㄥ` / `ㄐㄧㄝˊㄔㄥˊㄒㄧㄧㄚˇ` | 汉字（民汉译文即为汉字，如 `a06` scene0 row21「名字叫香坂　春风」） |
| 显示名 28 行 | `ハルカ` / `ノア` | `ㄔㄨㄣㄈㄥ` / `ㄒㄧㄧㄚ` | `春风` / `希亚`（汉化原包漏翻，上屏即注音，实机表现为「人名未翻译」） |

依据：`resource/official_cn` 中正文含注音 21 行、`name` 含注音 28 行；`resource/fonts_sc/SourceHanSansCN-{Bold,Medium}.otf` 的 cmap **全覆盖注音区**（U+3105–U+312F），所以不是豆腐块、而是读不懂的注音。改成汉字不泄底：正文 `a06` scene0 row21 / scene7 row82 早已写出真名，`？？？` 段的切换点一个没动。

判定方法（可复跑）：用 Windows 自带的 `Microsoft.VisualBasic.Strings.StrConv(…, SimplifiedChinese)` 逐字转换，转换结果与自身不同的字即繁体字形候选；本语料命中 27 字：`亞來別動嗎圍妳學幫從條現發結聽與著蘇話護過門開閒間頭風`。其中 `著` 在简体里合法（`原著`），只做词级替换。

> 语料（`resource/chs_text`、`resource/official_{jp,en,cn}`）已入库并经人工修订，是**唯一来源**；`script/extract_text.py` 仅留档，重跑 `--lang cn` 会把语料覆盖回民汉原件，须 `git checkout -- resource/chs_text` 取回修订版。

## 7. 四轨方案

官方三轨 jp/en/cn 全部保留，**新增第 4 轨 `sc`**：每行 `blocks` 从 3 个扩到 4 个（第 4 个是简中块，结构照抄 cn 块的 arity），每个选择支 `language` 追加第 4 项。工具链：

* `tool/psb.PsbGraph`：整图重排（`parse_graph()` → `PNode` → `build()`），17 个官方 scn 零改动**逐字节一致**；
* `script/extend_lang.py`：在官方 scn 上追加第 4 块 + 第 4 项，自带三道闸（幂等 / 前 3 块逐值不变 / 第 4 块等于语料）；
* `script/verify_lang4.py`：产物侧独立复核（`问题项 0` 才算过）。

第 4 轨在引擎里的定位：`LanguageTags` 追加 `sc`（索引 3），引擎按 `multiLangLanguageTags` 的序号取块（`GetScnConvertLangList()` 由引擎调用，返回 `en,cn,sc`）。字体固定在 `kag.chDefaultFace`（见 `engine-mechanics.md` §6）。
